# 知位 NEO · 生态位经营系统

> **读懂企业真实力，占住模型生态位。**
>
> 不是流量，不是盲推，不是排名优化，**与模型一起进化，构建你的生态位**。

**NEO**（Niche Ecosystem Operation，生态位经营）：不做搜索排名，不抢关键词，
而是让每个企业在**模型问答的生态里长出自己不可替代的位置**。

这里的 O 是 **Operation（经营）**，不是 Optimization（优化）：优化是"给定目标函数求极值"，
一次性、静态、面向某个引擎；经营是长期照料一块生态位，靠"构建 → 反馈 → 沉淀 → 再构建"的循环。
这也正是它与 SEO / AEO / GEO 的分野——那三个词都落在 Optimization 上。

## 为什么叫「知位」

AI 问答不是搜索引擎的替代品，它是一个**活的生态系统**：模型在换代，偏好在漂移，
用户问法在分化。传统 SEO/AEO/GEO 都在优化"一篇文章、一次曝光"，本质是**一次性博弈**；
这里要经营的是**长期生态位**——所以名字必须同时说清三件事：

| 字 | 含义 | 对应系统能力 |
|---|---|---|
| **知** | 真懂用户 | 会员画像 + 企业核心实力（资质/参数/案例/价格/服务）结构化沉淀，而不是编卖点 |
| **位** | 占生态位 | 6 模型 × 11 渠道的偏好规则矩阵，知道在哪类问法、哪个模型里你本来就该被引用 |
| **飞轮** | 越转越准 | 画像 → 定位 → 学规 → 育稿 → 投喂 → 复测 → 再学习，规则沉淀、模型迭代即重学 |

一条话概括：**知位把"投喂"从猜测变成有依据的经营**——知道自己强在哪、
模型爱引用什么、这一条该投给谁，再用复测结果反过来修正规则。

### 理论根基：生态位与生态位构建

名字借的是生态学的现成结构，不是修辞：

- **生态位（Hutchinson, 1957）**：把影响物种的每个资源/条件当作一根坐标轴，生态位就是它能存活的 n 维超体积；并区分**基础生态位**（无竞争时可占的全部空间）与**实际生态位**（被竞争压缩后真正占到的部分）。对应到本系统：企业本就该被引用的问法空间 vs 当前实际被引用的问法空间，两者之差就是**生态位缺口**——第 2 步的全模型基线测的正是"实际生态位"，可经营的增量就是缺口那部分。
- **生态位构建（Odling-Smee, Laland & Feldman, 2003）**：生物不只被动适应环境，也主动改造环境；改造后的环境反过来改变作用于自身与他者的选择压力（**互为因果**），并能跨代留存（**生态继承**）。对应到本系统：投喂改造了模型的信息环境 → 模型改变对你的表述 → 用户认知与竞品压力随之变化 → 规则与内容沉淀下来，模型换代后继续生效。
- 所以这里做的是**经营生态位**（Operation），不是**优化一次曝光**（Optimization）。

### 不是 SEO，不是 AEO，也不是普通 GEO

| | SEO / AEO | 普通 GEO | **知位 NEO** |
|---|---|---|---|
| 作用对象 | 网页 / 单条答案 | 单篇内容的引用概率 | **企业在模型生态里的生态位** |
| 出发点 | 关键词与流量 | 内容特征打分 | **企业真实核心实力**（没有的实力不写） |
| 对模型的态度 | 一套规则打所有引擎 | 抓通用偏好 | **逐模型逐渠道学规则**，承认各家口味不同 |
| 时间性 | 算法更新就重做 | 一次优化一次评测 | **模型迭代即重学**，规则带版本与置信度 |
| 结果 | 排名 / 曝光 | 提及率 | **可归因的提及率提升 + 可复用的规则资产** |

技术上，规则挖掘与内容特征来自 [AutoGEO](https://github.com/sybupt/AutoGEO)
（ICLR'26，生成式引擎内容优化）；知位在它之上补了三层：**企业画像与会员经营**、
**逐格（模型×渠道）规则学习**、**投喂—复测闭环**。

## 系统怎么转

**企业会员**（可推广品牌，也可推广某个产品）→ 多维度测试问题集 →
全模型提及率基线 → 规则矩阵学习 → 内容体检与改写（会员套餐渠道门控）→
引导投喂（链接/时长/目标模型登记）→ 效果看板（z 检验归因）→ 规则回流再学习。

```
知企              定位              学规
会员生态位台账  →  需求镜像问法  →  6 模型×11 渠道 66 格规则
(品牌/产品/级别)  (全模型通用)      + 模型×维度偏好
                                        │
复测            ←  投喂          ←  育稿
z 检验归因         链接/时长/模型     多模型选择 + 会员渠道门控
+ 规则回流          + 审核门禁          + 在线编辑审核
```

### 七块工作台（知位飞轮）

| 步骤 | 页面 | 说明 |
|---|---|---|
| 1 推荐流 | 企业会员 | 5 家模拟企业会员（茶叶/酒店/餐饮/企业服务/教育培训），每家标出**推广品牌还是推广产品**；点开详情有画像与渠道现状 |
| 2 测试问题集 | 维度问题集 | 按行业生成「参数党/口味/价格党/避坑/干净卫生…」多维度问法，**不绑定模型渠道**；一键测全部模型基线，读出各模型的维度偏好；支持**对话式出题**（右下角浮动窗口，文字或语音说一句要求，自动解析生成并入问题集；配置 `GEOREC_LLM_API_KEY` 走大模型理解，未配置走规则解析） |
| 3 规则与矩阵 | 规则学习 | 按目标物问题集学习「6 模型 × 11 渠道」全部格子的规则权重（AUC），AutoGEO 10 条规则可执行化 |
| 4 内容体检与改写 | 投喂稿生成 | 选**目标模型（可多选）**，按会员套餐自动带出可投渠道；每稿给改写前后同尺分数，支持在线编辑（重算分）与**审核** |
| 5 引导投喂 | 投放作业单 | 仅审核通过的稿子可登记；逐渠道记录链接、投喂时间、投放时长、针对模型与评分 |
| 6 效果看板 | 归因 | 投喂前后同一批问法 z 检验；投喂记录含模型与时长 |
| 会员管理 | 会员与套餐 | 会员名（企业主体）、推广对象、级别（缴费决定：试用 2 渠道 / 普通 2 万/年 6 渠道 / 高级 4 万/年 9 渠道）、到期与续费；付费会员与年度合同额汇总 |

内置示例会员企业（5 家：2 高级 / 2 普通 / 1 试用）：恩施玉露茶业（高级，推广产品）、
云栖湾酒店管理（高级，推广品牌）、千帐财税（普通，推广品牌）、知行教育科技（普通，推广产品）、
山塘里餐饮（试用，推广品牌）。另有 14 条竞品与 13 条话题型语料作为检索对手，
电子商品样例数据只留在语料库里，不再出现在推荐流。种子清单可增删，服务启动时会自动
清理不在清单里的企业及其派生数据。

## 快速开始

### 方式一：双击启动（推荐）

双击 **`start.bat`**，会自动校验依赖、缺数据时先跑流水线、起服务并打开浏览器。
服务跑在那个控制台窗口里，**窗口不关服务不停**；关窗口或用 `stop.bat` 停止。

### 方式二：命令行

```bash
pip install -r requirements.txt

python run_pipeline.py          # 生成合成数据 + 训练 + 离线评测（约 2 分钟）
python -m uvicorn app.api:app --host 127.0.0.1 --port 8000
# 浏览器打开 http://127.0.0.1:8000
```

### 打不开页面时的排查

1. **确认服务在跑**：命令行窗口里应有 `Uvicorn running on http://127.0.0.1:8000`；
   或执行 `netstat -ano | findstr :8000` 看是否有 LISTENING。
2. **端口被占**：先运行 `stop.bat`，或改用 `--port 8001` 后访问新端口。
3. **代理拦截本地请求**：如果系统设置了 HTTP 代理（如 Clash `127.0.0.1:5661`），
   浏览器可能把 `127.0.0.1` 也发给代理，结果是 502。把 `127.0.0.1` / `localhost`
   加入代理的「不走代理」列表，或先用 `http://localhost:8000` 试一次。
4. **提示 502 但服务其实活着**：同上，是代理返回的，不是应用报错。
5. **窗口一闪而过**：`start.bat` 必须保持纯 ASCII（cmd 用 GBK 解析 .bat），
   若自己改过脚本引入了中文注释，中文会被错误解码破坏脚本。

可选：接入真实 LLM 改写（OpenAI 兼容接口），不配置则自动使用离线规则改写：

```bash
export GEOREC_LLM_API_KEY=sk-...
export GEOREC_LLM_BASE_URL=https://api.openai.com/v1
export GEOREC_LLM_MODEL=gpt-4o-mini
```

## 离线评测结果（内置合成数据集）

| 模型 | Recall@10 | NDCG@10 | MAP@10 | AUC |
|---|---|---|---|---|
| 多路融合（无模型） | 0.3111 | 0.2454 | 0.1312 | — |
| 逻辑回归 · 仅协同/画像特征 | 0.3794 | 0.3237 | 0.1927 | 0.9087 |
| 逻辑回归 · 协同 + **GEO 内容特征** | 0.3796 | 0.3240 | 0.1928 | 0.9090 |

**冷启动专项**（16 个零交互新品，标签只用于评测、绝不进入训练）：

| 冷启动排序器（训练集相同） | AUC |
|---|---|
| 内容相似 + 类目/品牌/价格匹配 | 0.7084 |
| + GEO 内容质量与规则特征 | **0.7312**（+2.3pt） |

新品扶持位：88% 的用户至少有一个新品凭内容分拿到曝光位。

**结论（如实呈现）**：在成熟物品上，协同信号已把"内容质量"吸收掉，GEO 特征
只是边际增益；它的真正价值在 **冷启动排序**（没有协同信号时，文案质量就是唯
一可用的信号）、**推荐理由可解释**（规则分项直接变成推荐/不推荐的话术）和
**可运营**（改写低分文案、规则库给出全网 77.7% 商品"结论前置"不达标这类
可执行的洞察）。

## 设计要点（踩过的坑）

1. **特征穿越**：召回通道若把"已交互物品"分数置零，而训练正样本全是已交互
   物品，模型会学到"这些信号为 0 才是正例"，线上表现整体反向。特征侧必须用
   未置零的原始分（`channel_scores(mask_seen=False)`）。
2. **特征/标签错位**：`_build_X` 按用户分组写行、标签按原始顺序对齐，一旦
   pairs 不是按用户聚集就整列错位——不报错，只是指标 quietly 变差。现在按
   原始行号回填。
3. **共线性导致的权重翻转**：热度/类目与 usercf 高度相关，L2 太弱时符号随机
   翻转。标准化 + 适中 L2 后权重全部转正、可直接读作影响强度。
4. **占位符骗分**：改写器留下的"来源：待补充"曾被规则判为"已有来源"。
   检查器现在把占位行剔出证据。
5. **改写幂等**：GQS ≥ 85 的文案跳过改写——规则改写器不该把好文案"优化"差。

## 数据说明

真实推荐日志不可得，AutoGEO 公开数据集是"每问若干文档"结构、没有用户行为，
因此内置一个可复现的中文电商合成场景（`RANDOM_SEED` 固定）：420 用户 / 296
物品 / ~8900 次交互。关键在于保留了因果链

> 文案质量 q → 文案结构 → GQS（有噪观测）→ 排序特征
> 文案质量 q → 用户点击概率（隐变量）

所以 GQS 不是又一个拍脑袋的分数，而是对真实质量的观测，A/B 才有可解释的增益。

## 矩阵工作台（v1.1 新增）

在推荐系统之上扩展出「渠道 × 模型」的投喂闭环，五个新模块：

| 模块 | 路径 | 职责 |
|---|---|---|
| 注册表 | `app/cells/registry.py` | 6 个带检索的模型入口 × 6 个投放渠道，各带硬约束与先验 |
| 规则学习 | `app/geo/learn.py` | 从引用结果反推每格权重（逻辑回归），输出可解释规则卡 |
| 生成 | `app/distribute/generator.py` | 按格生成渠道版本，去极限词、织入品类词、补足字数 |
| 投喂 | `app/distribute/policy.py` | 渠道硬约束校验（字数/外链/标题/平台禁语），拦截后才可导出 |
| 检测 | `app/monitor/` | BM25 模拟检索探针 + 原稿 vs 改写稿前后归因（z 检验） |

前端新增「矩阵工作台」视图：36 格矩阵、每格规则卡（含不稳维度标记）、
生成结果（复制/导出）、效果检测（before/after + 逐 query 明细）。

**当前为模拟模式**：无真实模型 API，引用标签由模拟器生成（先验 + 渠道偏置 +
交互项 + 噪声），仅证明闭环可跑通；`source=simulated` 会如实标注。
接真实 API 时替换 `monitor/probe.py` 的 `_retrieve` 即可，归因逻辑不变。

关键设计决定：
- 「模型」维度只收录**带联网检索**的入口，纯离线 LLM 不会引用任何页面；
- 探针 query 必须包含**类目级问法**（只用商品全名提问 = 目标必中 = 自证）；
- 归因的 before/after 是**原稿 vs 改写稿**走同一检索器，唯一变量是内容。

调试中抓到的三个真问题（已修）：
1. 归因语料缓存键固定，第二次跑用的是旧语料（改写稿没进索引）；
2. 全文档 TF-IDF 余弦做检索打分，模板补充段稀释向量导致"改写稿反而检索不到"，
   换成 BM25（按查询词计分）后符合真实机制；
3. 改写会稀释品类关键词，生成器必须把品类词织进小标题，否则检索排名反而下降。
